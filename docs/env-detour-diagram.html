The .env Detour

Nine steps from "credentials.ts reads a variable that's never loaded" to ".env support that can't take the suite down" — including the fail-fast attempt that got tried, measured, and reverted.

  1. Problem. credentials.ts read STANDARD_USER/TTA_SECRET from process.env, but nothing ever called dotenv.config() — every run needed manual shell exports.
  2. Checked first. dotenv@17.4.2 was already a devDependency and already imported (unused) in playwright.config.ts. No install needed.
  3. Loaded it in the config, not a spec. playwright.config.ts runs once, before any spec is collected, so every later process.env read is guaranteed to see .env. quiet: true silences dotenv v17's promo banner.
  4. triedFail-fast. A requireEnv/assertEnv util that threw on a missing key, called at module scope in the spec — looked correct in isolation.
  5. foundThe hazard. Removing .env and running the whole suite printed Total: 0 tests in 0 files — a collection-time throw kills every spec, not just the one that threw.
  6. shippedFail soft instead. credentials.ts now falls back to real, working demo credentials with || (not ??, so empty strings fall through too).
  7. proofPrecedence, proven. Setting a bogus STANDARD_USER in .env makes login actually fail — confirming .env is read, not just the fallback.
  8. proofSafety, proven. Deleting .env entirely still collects all 8 tests and the spec still passes, on the fallback.
  9. resultNothing left that can throw at load time. The old util was deleted outright — no callers, no reason to keep it.

Proof 1 — .env is actually read

A value that can't possibly be a real account, set only in the file:

STANDARD_USER=env_proof_user
> login fails

Proof 2 — nothing can break

Remove the file altogether and re-collect:

mv .env .env.hidden
npx playwright test --list
> Total: 8 tests in 8 files
Reusable rule

Load dotenv once, in the framework's config file, never inline in a spec — config files run before spec collection, so there's no import-order race. And before adding a load-time throw anywhere, run the full suite with the file it depends on removed: a gitignored .env means "missing" isn't hypothetical — it's what every fresh clone looks like.
